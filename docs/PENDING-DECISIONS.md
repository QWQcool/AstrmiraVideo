### N5 · 配方 / 行业模板 / 引擎实例名要不要也做英文？（**存档**：已按 ① 拍板）

**先把事实摆清（都是代码里的事实）**：

- **界面文案**（按钮、提示、状态、标签）已经全部走字典；**下面这三类不是界面文案，是内容**：
  - `packages/shared/src/recipes.ts` 的配方（标题 + 骨架 + 坑位）、
  - `packages/shared/src/templates.ts` 的行业模板（行业 + 标题 + 骨架 + 摘要），
  - 引擎实例名（部署者在服务端配的，`/status` 里以 `label` 返回）；
  前两者合计 **58 条**（按 `id:` 计数）。
- 所以**英文界面下它们仍显示中文** —— 这是如实的状态，不是 bug（迁移到哪一步就说到哪一步）；
- 要让它们也有英文，代价是**给数据结构加英文字段 + 逐条写英文**。那**不是"翻译"**，
  是**内容创作**（骨架里写的是具体提示词写法：什么镜头、什么光、什么节奏）—— 机器替不了。

| 选项 | 形态 | 代价 / 收益 |
|---|---|---|
| **① 内容维持中文** ⭐ 我推荐 | 英文界面下配方 / 模板 / 实例名显示中文 | 零成本；代价是英文读者看到"英文外壳 + 中文素材"。但**素材本身就是中文写的**，先用起来比"翻译得半生不熟"更重要 |
| **② 内容也双语** | 给两份数据加 `*En` 字段并逐条写英文（58 条 × 2~3 个字段） | 需要真写 100+ 条英文素材，且**将来每加一条素材都要写两遍**（长期成本） |
| **③ 只双语标题、骨架保持中文** | 卡片名有英文，插入的骨架仍是中文 | 折中；但骨架中文会让英文用户的提示词里混中文 —— 半中半英的另一种形态 |

**结论（2026-10-20）**：按 **① 内容维持中文** —— 界面外壳继续 i18n，配方 / 模板 / 引擎实例名不译；见 [PLAN §6](PLAN.md) **D66**。将来若做内容双语，单独立项。

### N6 · 统一输入后，首页 Enter 是"提交"还是"换行"？（**已按 ① 拍板 → D69**）

**事实**：现在首页 `Enter = 提交`、`Shift+Enter = 换行`；节点 textarea 没有提交快捷键。
设计 §8 的目标是 **`Enter = 换行`、`Ctrl/Cmd+Enter = 提交`**，输入法候选确认不提交，`@` 候选打开时 Enter 先选候选。

| 选项 | 形态 | 代价 / 收益 |
|---|---|---|
| **① 按设计改（推荐）** | 两入口统一：Enter 换行，Ctrl/Cmd+Enter 提交；带 IME 组合守卫 | 中文输入更安全、两处一致；代价是改变首页现有肌肉记忆，需更新提示 |

| **③ 可配置** | 设置里切换 | 多一个设置项与两套路径，学习项目不划算 |
