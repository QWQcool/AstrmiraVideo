## 🔴 有一项等你拍板（2026-10-14 新开）

### N4 · H3 独立档怎么处理？

**先把事实摆清（都是代码里的事实，不是猜测）**：

- B4 的**自检**对 H3 档只能说一句实话：*"本服务没有可用的本地 MiniMax H3 后端（只有配置约定，没有可执行的推理 provider）"*
  （`backend/src/routes/providers.ts` 的 `describeUnregistered`）；
- 它的"检测"读的是**部署者配没配 `H3_WORKDIR`**（`statusProbe.ts` 只做目录存在性校验）——
  **它不会、也不可能自动发现你机器上的 H3 该怎么调**（自检只能验证**已知的约定**）；
- 更根本：H3 这一档**没有执行实现**（`registry.ts` 里 `'local-minimax-h3': () => null`，选了如实 503 PROVIDER_UNAVAILABLE）；
  写这个 provider 需要知道 H3 的**调用方式**（HTTP 端口 / CLI / Python 入口 + 提交与轮询约定 + 产物目录），
  而这**只有你机器上那份环境知道** —— 占位禁令下我不会去猜。

| 选项 | 形态 | 代价 / 收益 |
|---|---|---|
| **① 撤掉 H3 独立档** ⭐ 我推荐 | 引擎列表与自检里不再出现 `local-minimax-h3`；README / GUIDE 如实写明"本地轨 = ComfyUI（**H3 模型可以在 ComfyUI 里跑**）" | 半天内（前端 + 文档 + 测试）；收益是**界面上不再有一个"点了才知道不行"的档位**（那正是最糟的形态） |
| **② 做 H3 独立档** | 你给我 H3 的调用方式，我写 provider + 自检 + 真机验收 | 需你提供材料；且与 **D53（ComfyUI 一等公民）功能重叠**（H3 模型在 ComfyUI 里也能跑） |
| **③ 保持现状** | 档位留着、未实现、选了如实 503 | 零改动；但界面上摆着一个永远不可用的档，与"不假装可用"的精神相左 |
