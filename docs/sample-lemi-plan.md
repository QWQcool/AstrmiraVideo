# 样片执行卡 · 乐米艺术灯（B56）

> 用途：投资者**私下**看的 15~30s 抖音商业广告片样片。本文是这支片子的执行卡（口径 / 链路 / 分镜 /
> 提示词要点 / 预算 / 过程记录），**只放证据与参数，不放状态**（状态见 PLAN §5 与 §9-B56）。
> 素材与抓取产物一律放 `.tmp/`（**不进 git**：版权属乐米，仓库只留结论与参数）。

## 一、口径（用户 2026-10-09 确认）

- 私下聊用 / **15~30 秒** / **不露系统界面** / 完整商业广告风格，**可投抖音推广**（竖屏 **9:16**）
- **分辨率 = 720p**（用户 2026-10-09 拍板：节约成本；且 2.5 档的公开上限也是 720p）
- 片尾：**只放 logo + slogan**（不放二维码 / 门店信息）
- 音乐与动态节奏：**由执行方（AI）自行决定**，用户不看这两项的取舍（用户 2026-10-09 明确）
- 音乐：可商用授权曲（CC0 / 免版税，登记出处），B57 未落地前用 ffmpeg 混音并如实标注
- **制作路径（D43）**：成熟模型 / 工具优先；**不用我们自己的产品链路**（理由见 §五）

## 二、链路（为什么"素材够用"）

用户确认**拿不到乐米原图包**，只有官网 + 公众号的 58 张图（主流 819px 宽、横构图居多）。因此采用：

```
参考图（819px 干净图）  →  Seedream 5.0：参考生成"竖版 + 提清 + 同款灯"（图生图）
                        →  Seedance 2.5：图生视频（I2V，4~30s 单段、原生音频、竖屏）
                        →  剪辑/合成（拼接 + 字幕后置 + 混音）
```

**这条链路一次性解决两个缺口**：横图 → 竖版 9:16；819px → 1080 宽。

⚠️ **诚实边界（必须对投资人说清）**：
1. **不做 100% 产品还原**——AI 重绘会轻微改变灯具外观。口径是"**参考这些灯**做一支片子"（用户原话），
   不是"逐件还原产品图"；若将来要"1:1 还原"，需要乐米提供**白底原图 + 多角度**，且仍不保证完全一致。
2. 画面里的**中文与 logo 一律剪辑台后置合成**（模型写不准文字）。
3. **不用真人照片做首帧**（上游隐私检测会拒；B32 的实测教训）。

**首跑汇总（2026-10-09，v1）**：4 段视频 + 2 张图，**上游生成总耗时约 13 分钟（串行）、零重跑、一次通过**；
成片 **22.7s / 720×1280 / 30fps / h264+AAC，7.1MB**（`artifacts/sample-lemi/lemi-sample-v1.mp4`）。
**费用估算 ≈ 21 元**（435,600 tokens × 46 元/百万 ≈ 20 元 + 2 张图 < 1 元；**以方舟账单为准**）。

**首跑结论（链路与质量）**：
1. **链路全通**：参考图裁切 → Seedream 图生图（720×1280 竖版）→ Seedance 2.0（9:16 / 720p / I2V 与 T2V）→ ffmpeg（0.4s 交叉转场 + 中文字幕 + 音乐 + 慢推尾板）；
2. **"横图转竖屏"这一关键技法成立**：参考图（819~1080px 横图/长图裁切）经 Seedream 重绘后直接得到竖版 720×1280，且**风格与灯具形态保留**；
3. **"三色变光"视觉母题成立**（s2 首尾帧对比：冷白 → 暖黄，墙面光斑出现，镜头静止）；
4. 上游返回 **24fps**、且**自带 AAC 音轨**（本版改用音乐轨，未用其音轨）；单段 5s 计 **108,900 tokens**；
5. **纪律执行**：画面无任何生成文字；中文全部由 ffmpeg 后置；⚠️ 官网能抓到的 `/images/logo.png` 是**模板站自带的别家 logo（COMELY 新特丽）**，已弃用 → 尾板用**文字字标 `lemi 乐米` 占位**，**待官方 logo 矢量替换**。

**下一步可选（按需，不阻塞交付）**：① 换官方 logo；② 用 `2-5`（有声 / 30s 单段）重跑一版做 A/B；③ 字幕文案与 slogan 口径请乐米确认；④ 15s 短版（抖音信息流常用时长）可在同一批素材上直接剪。

## 五、为什么不用我们自己开发的产品（D43 的完整理由）

1. **缺口正好撞在这支片子上**：图片生成（B54-③）、BGM（B57）、单段 >10s（我方防线刻意限制 10s）
   ——三件都是广告片的刚需，而它们都还没接；
2. **成熟模型是同源的**：方舟 API 的 Seedance 2.5 / Seedream 5.0 就是"成熟模型"，即梦网页版另有
   3.5 Pro 音视频同步 / 数字人 / 智能多帧等更强的开箱能力，都属成熟工具；
3. **我们产品的价值不在"做一支片子"**：它是给企业**长期运营**用的（可复现 / 批量 / 审计 / 私有部署）。
   硬把它塞进样片流程，时间会花在"绕我们自己的限制"上，而不是把片子做好。
4. 代价如实说：走外部就**不产出"系统过程数据"**——所以本卡 §四 用**人工记录**把过程数据补回来，
   且对外表述为"我们用成熟模型产出的样片"，不冒充系统能力。

## 六、执行方式与成本估算（2026-10-09 讨论）

### 执行方式：**独立脚本直调方舟 API**（不是我们自己的框架）

八步全部由一个本地脚本 + ffmpeg 完成：脚本只做"提交任务 / 轮询 / 下载 / 重试"，**不 Import 本仓库任何业务代码**
（`backend/src` 一行都不碰）。这样它既不是"我们未完成的产品"，也不受我方防线（如单段 10s 上限）限制。

### 为什么不能用"登录即梦网页版"来调用

- **即梦（C 端网页）与 火山方舟（B 端 API）是两套系统**：登录即梦账号 ≠ 拥有 API 调用权；
  即梦网页版的独家能力（视频 3.5 Pro 音视频同步、数字人、智能多帧等）**没有面向个人的 API**。
- 想用即梦的企业能力，需要**在火山引擎侧单独开通"即梦 AI"API 服务**（另一条产品线与计费），
  与方舟的 Seedance/Seedream 是分开的（需要的话可去核开通路径）。
- **不建议**把浏览器登录态（Cookie）交给自动化脚本去驱动即梦网页：既违反平台条款、又极易触发风控封号，
  且不稳定。要走即梦独家能力，**人工点那一步**最稳（模式 B）。

### 成本估算（**以方舟账单为准**；公开报道的单价换算）

| 档位 | 公开单价（换算） | 5s / 720p 一段 | 全片 28s（含 2~3 倍重跑余量） |
| :-- | :-- | :-- | :-- |
| `2-0-mini-260615` | ≈ 0.5 元/秒 | ≈ 2.5 元 | ≈ 35~60 元 |
| `2-0-260128` | ≈ 1 元/秒（"1元1秒"报道） | ≈ 5 元 | ≈ 80~140 元 |
| `2-5-260628` | 比 2.0 贵 60~75% | ≈ 8~9 元 | ≈ 130~220 元 |

Seedream 生图：≈ 0.2~0.5 元/张，5~8 张可忽略不计。**首帧可选**：Seedream 5.0-pro / 5.0-flash / 4.0（三档已开通）。

### 建议的试跑方案（成本最小，先验风格）

1. **试跑 A（约 3~10 元）**：S1 用 **`2-0-mini`** 出 1 段 4s（验证"暗场点亮 + 色温流动"的观感），
   同时用 Seedream 出 1 张"参考小吊灯 → 竖版 720×1280 提清图"（验证"横图转竖屏"这一步不掉相）；
2. 风格确认后再决定正式档（`2-5` 有声 / `2-0` 高分辨率 / `mini` 省钱）跑全片；
3. 每段先给**抽帧预览**，通过再进合成。

## 七、v2 方向：人物出镜（2026-10-09 用户提出；探讨中）

**用户诉求**：希望有一个**人物快速介绍灯光相关内容**（口播/出镜），像正常广告片那样。

### 为什么 v1 里没有人（三层原因，逐条有据）

1. **上游对"含真人脸的输入图"有隐私检测**（本项目实测，见 `seedanceProtocol.ts` 证据段与 PLAN 台账 B32）：
   用含拟真人脸的图做**首帧**会被 400 拒（`InputImageSensitiveContentDetected.PrivacyInformation`）。
   → 所以"拿乐米或网图的真人照片当首帧"这条路**本来就是封着的**（这不是我们的取舍，是上游约束）。
2. **口型对不上**：方舟 API 的 Seedance 2.0/2.5 **没有口型同步**（音视频同步是即梦网页版 3.5 Pro 的能力）。
   人物说话但嘴不动/对不上，在 15~30s 的广告里**非常出戏**。
3. **v1 的目标是"跑通链路"**：首跑选最稳的 5 段光影镜头（无人物依赖），把人物留到第二版 —— 属**刻意留到下一步**，
   不是不能做。

### 版权 vs 肖像 vs 标识（把风险分清楚）

- **版权**：AI **生成**的人物形象不侵犯他人版权（是新生成内容）——这一层不必担心。
- **肖像权**：真正的风险在这 —— 生成的形象**不得与真实人物（尤其明星/公众人物）相似**；用真人出镜必须拿到
  本人**肖像授权**（模特合同）。
- **AI 标识义务**：法规（《人工智能生成合成内容标识办法》，**2025-09-01 起施行**，以官方原文为准）与
  抖音平台都要求 **AI 生成内容发布时做显式标识**（抖音发布时勾选"AI 生成"）。私下给投资人看不涉发布，
  **但一旦投抖音推广，这一步必须做**。
- **广告法**：人物台词里避免功效性宣称（"护眼/治疗"一类）；产品属性（三色变光 / 全光谱）与品牌主张
  （"让每家拥有健康光"，乐米官方口径）相对安全 —— 文案仍以乐米确认为准。

### 四条可选方案（按"稳 → 炫"排序）

| 方案 | 做法 | 口型 | 肖像风险 | 成本增量 | 建议 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| **A 手部/局部出镜** | 只出现"人的手调光/开灯/翻书"或背影走过 | 不需要 | **几乎为零** | +1 段（≈5 元） | ★★★ 最稳，广告里最常见 |
| **B 人物 + 旁白（画外音）** | AI 生成人物做动作/展示灯，讲解走旁白 | 不需要（避开） | 低（形象不与真人相似即可） | +1~2 段 + 配音 | ★★★ 推荐：既有"人味"又不搏口型 |
| **C 人物 + 口播（要口型）** | 需即梦网页版 3.5 Pro 或数字人能力 | 需要 | 低~中 | 需人工跑即梦 / 另开通 | 想要"主播式"再走这条 |
| **D 真人实拍** | 乐米提供模特或实拍素材，我方剪辑 | — | **需肖像授权** | 取决于拍摄 | 客户有素材时最真实 |

**旁白/配音三条路**：① 用 Seedance **2.5 的原生出声**（提示词内写台词，需实测中文念白效果）；
② 外部 TTS 生成配音再混音（可控、便宜）；③ 乐米真人录音（最真、要安排人）。

### 建议的验证步骤（先花小钱验风险，再决定方案）

1. **第一步（≈5~10 元）**：跑一段 5s **T2V 人物测试**——"一位年轻女性在客厅里伸手调灯的色温"，
   验证两件事：上游**允许 T2V 生成拟真人人物**吗？生成的**脸与手**质量够不够广告用？
2. 通过 → 按方案 B 做 v2（出镜 4~6s 开场 + 旁白讲解，v1 的五段光影镜头保留复用）；
   不通过 → 退方案 A（手部/局部）或 D（实拍）。
3. v2 若投抖音：**发布时勾选"AI 生成"标识**（平台要求），并确认台词口径。
