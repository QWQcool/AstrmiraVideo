# Astrmira 创作体验 · 交互定稿 V1

日期：2026-10-19；执行口径复核：2026-10-20。用途：创作体验设计基准。实现与待验项以 [PLAN §5](PLAN.md#creation-experience-status) 为准，不以概念图或旧原型推定功能已经通过验收。

实施顺序、完成状态、验收门槛统一见 [PLAN §4 Step 11](PLAN.md#creation-experience-plan)；本文件负责交互、视觉与证据。后续调整在同一版本基础上记录，不另开一份施工计划。

> **2026-10-19 追加（登录态实测，见 §7）**：经用户登录会话逐屏观察，本稿大部分成立，需要修正的是两处：
> ① 画布的创作框是**贴着选中节点的浮动面板**（不是"页脚共享输入区"，也不是"卡片内部"）；
> ② 添加菜单实际是 **9 项**（多出时间线/主体/导演台）。
> **首页的视频/图片切换与参数条是存在的**——先前的"首页没有参数"是观察错误（当时停在 Agent 模式）。
> 结论：**本稿（V1）仍作为定稿基准**；`docs/design/creation-v2` 的三张图**未采纳**，仅存证。

## 3. 页面与视觉规范

### 3.1 导航与尺寸

- 桌面主导航宽 208px；四个常驻入口；最近创作最多显示 6 项，其余从作品检索。原型展示 2 项。
- 主创作区最大宽 1100px；输入框、参数与提交属于同一个容器，半径 20px；留白基于 8px 步长。
- 首屏顺序：标题 → 生成 / 画布切换 → 创作输入 → 配方起手式 → 最近作品。默认不堆叠宣传卡片。
- 画布采用收敛的顶栏、点阵背景、媒体节点、上下文操作条与底部输入区。原型为统一侧栏，后续可按同一导航规则折叠。
- 1440×960 为桌面校验尺寸，1366×768 / 1920×1080 为生产验收尺寸；≤760px 保留浏览与创作表单，画布提供桌面提示和作品入口。移动端不承诺完整编排编辑。

### 3.2 设计令牌

| 用途 | 定稿值 |
|---|---|
| 页面 / 面板 / 悬浮层 | `#111315` / `#1C1F22` / `#262A2E` |
| 主文字 / 次文字 / 边框 | `#EFF1F1` / `#939A9F` / `#32373B` |
| 选中与主要操作 / 品牌 | `#67DCF2` / `#DDBD83` |
| 字体 | 系统无衬线：Segoe UI、Microsoft YaHei、sans-serif |
| 字号 | 页面标题 36px；区块 21px；输入 16px；正文 14px；辅助 12px；移动端正文至少 12px |
| 控件 | 常用按钮高 36–42px；圆角 10px；媒体卡圆角 12px；弹层 18px |
| 焦点与动效 | 2px 青色键盘焦点环；反馈过渡约 150ms；遵循 reduced-motion |

视觉图中的文字、图标由生成模型绘制，生产实现采用现有图标体系与真实文字；不引入整套新 UI 框架。原型中的字符图标用于交互定位，不能作为最终图标资产。

## 4. 交互规则

### A. 首页创作

1. 进入「创作」，恢复当前项目的草稿。视频与图片是输出目标；切换不清空文字与素材。
   （实现上，"视频/图片"由输入区的**创作类型**选择器承担；选到视频/图片后才出现模型、参考模式、比例、清晰度、数量、时长与费用。
   这是 2026-10-19 实测确认的形态，见 §7.2。）
2. 点击参考素材 / 输入 `@` 打开同一选择器；拖入文件直接上传并加入当前草稿。素材显示缩略图、名字、类型、输入用途；移除引用不删除源文件。
3. 选择模型后，界面按其能力约束显示比例、清晰度、时长、数量、参考类型和数量上限。旧参数不兼容时明确标记，需要用户选择兼容值；不偷偷换模型或舍弃素材。
4. 配方只插入描述，行业模板填写起手式；不会自动提交，也不把模板名当作模型能力。
5. 费用来自已有估算机制；没有可信报价显示「费用待核算」，不能显示 0 元、伪积分或假用量。
   **本产品不做用户系统、支付、充值、积分与会员**（见 PLAN D59）：界面不出现积分余额、会员标识、充值入口；
   参考稿里的"56/30 积分""标准会员"是对方商业体系，不属于我们的规格。
6. Enter / Shift+Enter 换行；提交按钮与 Ctrl / Cmd + Enter 使用同一校验与幂等逻辑。输入法组合输入期间不提交；候选菜单优先处理键盘；重复点击不创建重复任务。
7. 任务在当前创作上下文显示；成功后可继续创作、作为参考、放入画布、下载；视频可转入现有剪辑台。

### B. 模型未配置与不可用

| 状态 | 展示 | 允许操作 |
|---|---|---|
| 未配置 | 「图像模型待配置」+ 接入要求；生成按钮停用 | 编辑 / 保存草稿、管理素材、查看配置入口 |
| 验证中 | 显示正在验证与取消；不展示“已可用” | 保留草稿、切换已验证的其他模型 |
| 配置错误 / 离线 | 可读原因、重试验证、设置入口 | 查看原因；明确选择其他模型 |
| 就绪但缺能力 | 例如「此模型不支持局部编辑」 | 保留支持的文生图；仅停用不支持的工具 |
| 可用且有能力 | 当前模型名称、真实参数范围 | 提交对应操作 |

图片切换后的默认空配置状态是本次交互稿重点，**不预选具体生图模型、不安装模型、不假设“填名称就可用”**。现有已验证的 ComfyUI 文生图可作为兼容候选，不强制替换。

### C. 画布

- 点击节点：显示媒体预览与适用操作条；输入区锚定选中节点、按视口选边。选中图片作为首帧时明确目标节点；点击空白处取消选择。旧原型的全局底部框只作视觉参考。
- 拖动节点只改变布局；空白处拖动平移；缩放保留当前工作中心；「适应画布」定位全部内容。
- 添加菜单包含文本、图片、视频、音频、从作品添加、本地上传。音频先作为素材管理与剪辑输入，不能暗示任意视频生成模型支持音频参考。
- 多参考需要明确输入用途与顺序；生成前展示素材绑定。首尾帧与通用多参考是不同语义。
- 当前连线是来源关系，与草稿输入绑定同步；它不触发任务执行。待执行依赖仅为后续预留，不能因画了一条线就自动生成；移动卡片只改布局。
- 节点提交在原节点追加任务批次，运行/失败状态不覆盖上一成功预览；显式“作为参考继续”才新建相邻草稿节点。所选版本决定结果动作，历史参数从对应任务读取，缺失时明确说明；详见 §8.3。
- 「移除节点」只移除画布引用；「删除作品文件」属于独立资产动作，不能混为一个菜单项。
- 跨会话保存画布名称、节点、布局、输入与来源关系；撤销/重做只撤销编辑动作，不能撤回已提交任务或已发生费用。
- 不新增“免费试跑”产品能力。可点击稿中的演示状态按钮仅用于设计审阅，生产版本必须移除（与 D54 一致）。

### D. 作品复用

「作品」统一图片与视频，筛选按类型、项目、名称、时间；详情显示来源任务与生成参数。作为参考将所选资产绑定到输入区；放入画布复用已有资产，不重新上传副本。缺失文件 / 无权限 / 已清理状态明确提示，禁止产生失效引用。

### E. 失败与恢复

| 情形 | 行为 |
|---|---|
| 空提示词 / 不支持的素材组合 | 输入区就地指出原因，禁止无效提交 |
| 上传中 / 上传失败 | 每个素材单独显示进度与重试；上传完成前不能引用 |
| 排队 / 运行 | 真实状态与排队提示；未知进度不编造百分比 |
| 取消 | 展示取消中，收到服务端终态后再显示已取消 |
| 失败 | 保留提示词、参数与引用；展示可执行建议及错误详情入口 |
| 重试 | 生成新的执行记录并关联原失败任务；已有幂等语义继续有效 |
| 刷新 / 返回 | 恢复草稿和任务上下文；不能重复提交 |
| 图片模型未配置 | 停用生成、保留编辑能力，说明所需配置 |

## 5. 图像能力接入设计

以下是设计要求；已有契约以 [CONTRACT §21](CONTRACT.md) 为准。能力与画布 schema 已落地不代表所有调用点已完成接线；缺口按 PLAN S4-R3 验收，新增协议仍先修改 CONTRACT。

1. **模型目录**：显示名称、模型标识、提供方、适配器类型、就绪状态；模型目录中不保存明文 Key。
2. **能力描述**：文生图、参考图生图、局部修改、扩图、抠图、高清分别声明；同时声明输入用途、数量上限、格式、尺寸、输出数量和价格来源。没有能力声明就不开放。
3. **提供方适配**：复用现有任务提交 / 查询 / 取消 / 产物归档机制；ComfyUI 需要对应工作流与字段映射，其他提供方需要实际适配器。接入新增协议仍需要开发与验证。
4. **资产契约**：图片任务输出能作为下一次图片 / 视频任务的明确输入；不能把图片产物硬塞进视频字段。引用保留资产 ID、用途和来源，不仅存一个临时 URL。
5. **配置与凭据**：部署者提供服务地址、模型或工作流、能力映射；云端凭据继续遵循项目既有 BYOK 零留存规则。没有新的服务端托管 Key 决策。
6. **接入验收**：连接与模型存在性、一个最小真实任务、产物类型、取消 / 超时、不可用状态、费用口径逐项验证。未执行真实模型验收时只能标注“适配待验证”。

UI 骨架、素材画布与视频继续创作可以先做；实际生图与每项图像编辑以对应模型接入完成为启用条件。

### 7.2 首页（创作）

  `最近上新` 工具卡（智能编辑、视频局部重拍、智能超清、提示词反推、3D 导演台、图片多角度、深度动作捕捉、智能打光、720 全景、3D 渲染插件）→ 精选作品瀑布流（分类 tab + 搜索）。

- 画布态（`?createTab=canvas`）把输入区换成「新建画布 / 模板·视频创作 / 模板·图像创作」三张卡，下方仍是同一输入框与工具卡。

### 7.3 画布

- 路由独立：`/ai-tool/ai-canvas/<canvasId>`；首页只承载入口。
- 顶栏：项目名 + 节点数 + 保存状态 + 分享 + 搜索 + 生成历史 + 积分 + 用户菜单。
- 左侧竖排工具栏（9 项）：文本、图片、视频、音频、**时间线**、**主体**、**导演台**、资产库（标 `New`）、上传。

- 节点左右各有一个 `+` 连接柄；点阵背景；无全局输入条。

### 7.4 节点（以视频节点为例）

节点 = **媒体预览区**（卡片本体）+ **锚定创作框**（选中时浮出的独立层，DOM 是 React Flow 的
`react-flow__node-toolbar`，`z-index` 远高于卡片，位置跟随选中节点，**不在卡片内部**）：

- 预览区：空态显示上传图标与"上传参考图、输入文字或 @主体，描述你想生成的视频"。

- 模型菜单：每项带一句能力描述、`VIP` 标记；不兼容时**就地禁用并给理由**（原文："已使用全能参考，暂不支持此模型"）。

### 7.5 资产页

- 空态为"暂无相关资产"；页面无全局输入条（与首页不同）。

### 7.6 画布 AI 侧栏

- 右侧抽屉「新会话」；空态给 **专业创作模式** chips：`/视频反解`、`/创作分镜`、`/全流程广告片导演`、`/剧本开发`、`/剧情短片`。

### 7.7 技术实现对照（观察所得，非源码级）

| 层 | 实测 | 对我们的含义 |
|---|---|---|
| 画布容器 | DOM 出现 `rf__wrapper`、`canvas-dot-grid`、`canvas-connection-flow-layer` | **React Flow**（我们已用 XYFlow，可直接复用同一套） |
| 节点类型 | 独立懒加载 chunk：`async-canvas-node-{text,image,video,audio,file,group,external,timeline,subject}` | 节点类型必须可插拔；不要把所有节点塞进一个 bundle |
| 富文本 | `tiptap` / `ProseMirror`，`@` 为行内节点 | 我们要么引入 tiptap，要么用 chips 折中（S2 决策） |
| 文档模型 | `document.nodes/edges` + `_edgeIdsByRelationKey` + `_incidentEdgeIdsByNodeId` + undo/redo service + change diff | 画布需要**编辑器内核**（撤销栈、批量变更、边关系键），不是 DnD 容器 |
| 节点数据 | `{id,type,createdAt,layout{x,y,width,height},meta{createdFrom,createdByActor},data}`；`data.generationDraft{kind,parts[],contentSettings{mode,modelName,aspectRatio,resolution,durationSeconds,isLongVideo},outputCount,references[]}`；`data.resourceBatches[]`；`data.source` | 我们的 `CanvasPlan` 需要补"节点草稿 + 产物批次 + 布局 + 来源"，否则刷新即丢 |
| 协作 | `Room connected` + `async-canvas-collaboration-runtime` | 我们**不做**，但持久化要能换成服务端文档而不改 UI |
| 路由 | `/ai-tool/ai-canvas/<id>`；首页 `?createTab=canvas` | 画布需要独立 URL 才能分享/刷新恢复 |

### 8.2 保留与取舍

- **直接复用**：已有上传/拖放/图片粘贴、任务执行与状态、图片/视频输出、媒体预览与下载、资产 ID、文档保存、来源边、批次、撤销栈及本地 ComfyUI 适配。可靠性问题按 PLAN R1/R2 先修；本轮不重写这些基础。
- **需要改善**：编辑与参考语义跨入口一致、草稿完整恢复、画布直接操作、历史版本的可见选择、结果继续创作和统一视觉。满足这些后才能称“连续创作体验收口”，功能菜单齐全不代表完成。
- **继续预留**：具体生图模型及新增图像编辑能力。现有 t2i 可用能力如实展示；更换模型通过能力和适配配置落地。只有真实接通才开放多参考、改图、扩图、抠图等操作。
- **保持原边界**：不增加会员/充值/积分、社区、多人协作、主体库、数字人、时间线或导演台；旧编排不迁移。技能与 Agent 的时序由 PLAN 管理，不用它们补偿基础交互不足。

### 8.3 本项目目标交互规则【规划】

下列是给后续实现的统一规则，优先于旧原型中的冲突行为；步骤、优先级与 AC 只在 [PLAN Step 11](PLAN.md#creation-experience-plan) 维护。

#### 输入与引用

- 首页和节点使用同一套编辑行为及参数组件，宿主负责各自草稿/保存；首页可切输出类型，节点按现有类型编辑，选择其他节点不改写原节点类型或草稿；不增加第二套任务系统。保留既有上传与粘贴行为，文件直接进入上传流程，不要求先打开素材弹窗。
- `@` 目标为**结构化行内引用**，显示缩略标识/名称，与素材区域的用途绑定同一稳定引用；普通文字中的 `@` 不自动变资产。选候选、删除、撤销、复制粘贴都有明确降级：复制到纯文本目标只保留名称，不能带临时预览 URL；从纯文本粘回不凭名称猜资产。持久化表示变化先改 CONTRACT；优先复用现有 React 组件，富文本库由最小验证决定，不因对方使用 Tiptap 就强制引入。
- 行内引用与素材区不是两份独立清单；移除引用同时移除相应绑定/标记但保留周围文字，撤销同时恢复；提示词序列化与实际输入用途保持一致。未接入的图片参考能力不因为编辑器能插入标记就可提交。
- 首帧、尾帧、参考视频显示独立用途；两个有效图片位可交换。全能参考仅在真实模型支持时出现。类型/模型切换保留输入，不兼容项就地标记，禁止以自动丢引用的方式“修好”请求。
- 模型、参考模式、比例、清晰度、数量、时长按能力显示，费用和提交在尾部；数量当前固定 1。图片不显示视频时长；无报价显示“费用待核算”。高级连接设置不占主参数行。
- 有效已上传素材跨刷新按 ID 恢复；上传中断不能伪装成功，也不尝试重放无法恢复的本地 File 对象。恢复失败保留素材名与原因，允许重选/移除。显示“草稿已保存”必须与实际持久化结果一致。

| 操作 | 统一行为 |
|---|---|
| Enter / Shift+Enter | 换行；`@` 候选打开且有活动项时 Enter 选候选 |
| Ctrl/Cmd+Enter | 显式提交，走与按钮相同校验和幂等逻辑；输入法组合期间不提交 |
| 中文输入法 Enter | 仅确认候选，不生成；需考虑 composition 事件顺序并用真实输入法验证 |
| Esc | 先关闭最上层候选/参数弹层/预览，返回触发项；不清空草稿 |
| 移除参考 / 撤销 | 只改当前草稿绑定；不删源资产、不触发新任务 |

#### 画布与浮层

| 操作 | 统一行为 |
|---|---|
| 单击节点 / 空白 | 选中并显示适用工具与锚定编辑区 / 取消选择并关闭局部菜单 |
| 空白双击 / 右键 | 在指针位置打开添加菜单；只提供已支持的节点类型及素材入口 |
| 空白拖动 / Space+拖动 | 平移；Space 在编辑区内仍是文字输入，不被全局处理 |
| Shift+空白拖动 / Shift+点选 | 框选 / 增减选择；节点拖动仍只改布局 |
| 鼠标滚轮 / 触控板 | 鼠标滚轮以指针为中心缩放；触控板双指平移、捏合缩放；保留可见缩放与适应按钮。以真实设备验证，必要时提供手势设置，不让浏览器页面缩放抢走画布操作 |
| 文件拖入 / 系统图片粘贴 | 指针落点 / 最近有效画布指针位置（没有则视口中心）创建上传节点；不调整全图视口；输入区粘贴则添加当前草稿参考 |
| 节点复制粘贴 / 撤销重做 | 保留已有节点复制；文本与系统媒体剪贴板不被私有节点剪贴板覆盖；编辑器和弹窗优先处理自身快捷键 |
| 返回画布 / 状态刷新 | 恢复该画布有效视口；普通输入、轮询更新不触发 fitView；首次无有效视口或显式点击适应才全图定位 |

浮动面板按真实宽高与可用视口避让，不用固定阈值假定永远放得下；选中媒体与生成按钮保持可见。长文本内部滚动，靠边节点不因输入每个字持续换边。窄屏空间不足时允许同一选中节点面板转为底部抽屉，须保留节点名称/缩略图及关闭入口，**不再另造一条全局创作框**。节点工具条与编辑区都不能提供尚未接通的改图/超清等假按钮。

#### 版本与续作

- 批次计数打开按时间排列的版本列表，成功项有缩略图/时间，失败与运行项有明确状态。当前预览可以是旧版，最新任务状态仍单独可见；状态更新不抢走用户已选的版本。
- 未手动选版时沿用“最近成功产物”；手动选版后，预览/下载/作为参考/新连线都绑定这个产物。手动选择按节点保留，切换画布/刷新后仍查看所选产物；若该产物已不可用则明确提示并允许重新选择，不静默换成别版。所选版本持久化需要先补 CONTRACT，不能复用草稿或状态字段冒充；已有引用始终固定原资产，不能被预览切换影响。
- **原节点再生成**：使用当前草稿，追加批次，原成功产物保留；**作为参考继续**：从所见版本建立兼容的邻近新草稿节点与来源关系（当前图片可续作视频，不暗示已支持图生图），焦点进入其输入区，仅在当前视口容不下时作最小平移，不自动提交；无兼容能力时保留当前结果并说明原因。
- **复用参数**：从所选版本真实任务记录读取提示词/设置/引用并按当前能力检查；任务已清理或字段未记录时说明缺项。已有非空草稿不能静默覆盖；采用保留原草稿的返回/撤销方式，避免每次复用都增加确认弹窗。当前批次结构没有完整参数快照，若需补存先修改契约，不使用当前节点草稿推测历史。
- 首页、资产、画布使用统一预览组件及可用动作。预览可在当前明确集合内切换结果/版本，显示当前项；Esc/关闭后回原卡片或节点。若当前入口仅有一个结果，就不显示无用的上一项/下一项。

#### 视觉与反馈

沿用 §3 数值与 V1 方向：主区保留呼吸空间，工具信息收敛为紧凑参数行，媒体缩略图与选中态突出，长提示词不把画布挤成表单页。所有页面共用字体、间距、焦点、选中、禁用、加载、错误与保存状态的表达。菜单支持方向键/首尾项/Enter/Esc；模态层打开后焦点留在层内并暂停背景快捷键，关闭后回触发项；错误文案先说可采取的动作，详细错误可展开。

实机交互与截图验收场景统一见 PLAN J1–J5。本轮没有采集时延、帧率或相似度数据，不宣称已经达到即梦手感。
